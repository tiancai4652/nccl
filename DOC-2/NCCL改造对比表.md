# NCCL CPU化改造 - 核心变化对比表

## 🔍 快速对比总览

| 组件类别 | 原版NCCL | CPU化改造版 | 变化原因 |
|---------|----------|------------|----------|
| **GPU设备** | 需要真实NVIDIA GPU | 虚拟GPU（通过环境变量控制数量） | 去除硬件依赖 |
| **CUDA库** | 依赖系统CUDA Runtime | fake_cuda虚拟实现 | API兼容但CPU执行 |
| **编译器** | 需要真实nvcc | 虚拟nvcc（将.cu转.cpp） | 支持CUDA代码编译 |
| **拓扑信息** | 硬件自动扫描 | XML配置文件 | 可配置的虚拟拓扑 |
| **内存操作** | GPU显存操作 | CPU内存操作 | 保持API兼容性 |
| **核心算法** | **完全不变** | **完全不变** | 保证算法选择一致 |

## 📋 详细功能对比

### 1. CUDA API处理

| CUDA函数 | 原版行为 | CPU化行为 | 实现方式 |
|----------|----------|-----------|----------|
| `cudaGetDeviceCount()` | 查询真实GPU数量 | 返回环境变量`GPU_DEV_NUM` | 环境变量控制 |
| `cudaSetDevice()` | 切换到指定GPU | 记录线程与虚拟设备绑定 | 线程本地存储 |
| `cudaMalloc()` | 分配GPU显存 | 调用`malloc()`分配CPU内存 | 内存类型转换 |
| `cudaMemcpy()` | GPU内存拷贝 | CPU内存拷贝或忽略 | 拷贝类型判断 |
| `cudaStreamCreate()` | 创建GPU流 | 返回虚拟流句柄 | 句柄模拟 |
| `cudaLaunchKernel()` | 启动GPU核函数 | 立即返回成功 | 跳过GPU执行 |

### 2. 环境配置对比

| 配置项 | 原版NCCL | CPU化版本 | 作用 |
|-------|----------|-----------|------|
| `CUDA_HOME` | `/usr/local/cuda` | `./fake_cuda` | 指向虚拟CUDA |
| `nvcc路径` | 系统nvcc | `./fake_cuda/bin/nvcc` | 虚拟编译器 |
| `拓扑来源` | 硬件扫描 | `NCCL_TOPO_FILE` | XML配置文件 |
| `GPU数量` | 硬件检测 | `GPU_DEV_NUM=4` | 环境变量控制 |
| `调试信息` | 有限 | `NCCL_DEBUG=TRACE` | 详细日志输出 |

### 3. 文件结构变化

| 目录/文件 | 原版NCCL | CPU化版本 | 新增内容说明 |
|----------|----------|-----------|-------------|
| `src/` | ✅ 存在 | ✅ 保持不变 | 核心算法代码不变 |
| `fake_cuda/` | ❌ 不存在 | ✅ **新增** | **完整CUDA虚拟化层** |
| `├── include/` | - | ✅ **新增** | 130+个CUDA头文件 |
| `├── lib/` | - | ✅ **新增** | 虚拟CUDA库文件 |
| `├── src/` | - | ✅ **新增** | fake_cuda实现代码 |
| `├── bin/nvcc` | - | ✅ **新增** | 虚拟nvcc编译器 |
| `topo/` | ❌ 不存在 | ✅ **新增** | **XML拓扑配置** |

## 🔧 核心改造技术

### 1. 虚拟化技术栈

```
应用层：    用户代码 (无需修改)
          ↓
API层：     NCCL API (完全兼容)  
          ↓
算法层：    算法选择逻辑 (完全保持)
          ↓
虚拟层：    fake_cuda (★核心创新★)
          ↓
系统层：    Linux CPU环境
```

### 2. 符号替换机制

| 链接阶段 | 原版NCCL | CPU化版本 |
|---------|----------|-----------|
| **编译时** | 找到系统CUDA头文件 | 找到`fake_cuda/include/` |
| **链接时** | 链接系统CUDA库 | 链接`fake_cuda/lib/` |
| **运行时** | 调用GPU函数 | 调用虚拟CPU函数 |

### 3. 保真性保证

| 保真项目 | 实现方式 | 保真程度 |
|---------|----------|----------|
| **算法选择** | 完全使用原版逻辑 | 100%一致 |
| **拓扑分析** | XML模拟硬件拓扑 | 高度一致 |
| **性能模型** | 保持原版计算公式 | 完全一致 |
| **通信流程** | 记录而非执行 | 逻辑一致 |

## 💡 关键理解要点

### ✅ 什么没有改变（核心保持）
- **算法选择逻辑** - Ring、Tree、CollNet等算法选择完全不变
- **性能评估模型** - 带宽、延迟计算公式保持原样
- **通信模式生成** - AllReduce、AllGather等模式逻辑不变
- **API接口定义** - 所有NCCL API保持完全兼容

### 🔄 什么发生了改变（虚拟化层）
- **硬件依赖** - 从真实GPU改为虚拟GPU
- **CUDA调用** - 从GPU执行改为CPU模拟
- **拓扑获取** - 从硬件扫描改为XML配置
- **执行方式** - 从真实执行改为流程记录

### 🎯 改造的核心思想
```
保留大脑（算法逻辑）+ 替换手脚（硬件接口）= CPU化NCCL
```
